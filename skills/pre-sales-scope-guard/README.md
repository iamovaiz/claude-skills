# pre-sales-scope-guard: stop doing the paid work before you're paid

The prospect asks for a quick proposal. Then "a bit of market research". Then an MVP so they can see it. Three weeks later you've built the thing, and the deal is still a maybe.

With AI, a research report or a working prototype takes an afternoon, so it feels cheap to give away. It isn't cheap. It's what you sell.

This skill keeps Claude's effort in proportion to the deal:

| Deal stage | Worth producing |
|---|---|
| First contact | A reply and discovery questions |
| Discovery call done | A proposal with 2 or 3 priced options |
| Paid discovery agreed | Research, audits, a prototype |
| Contract signed | The build |

When a request belongs to a later stage, Claude says so first and offers the smaller piece that fits, plus a paid discovery offer for the rest.

## It also checks

- **The facts behind any price:** budget, who decides, the real problem and how success is measured, and for commission deals, the commission and margin. Missing facts are listed as Known, Assumed or Unknown, and estimates built on them are labelled.
- **Misdiagnosis:** whether it's a process problem that software would only speed up.
- **Hidden scope:** hardware, data migration, integrations, training, support.
- **Red flags:** results-only pay with no past data, claims that can't be checked, several decision-makers, requests that grow after every delivery.
- **AI research:** two models agreeing isn't verification.

It advises; it doesn't refuse. If you choose to do free work for a strategic client, it helps you do it well.
